# ADR-0002: استثنای REST برای ارتباط S3 با S1

- Date: 1405/08/18
- Status: Accepted
- Deciders: تیم S3 (Payment Orchestration)
- Tags: architecture, inter-service, rest, s1, testing
- Related: ADR-0001

## Context

ADR-0001 ارتباط بین‌سرویسی S3 با سرویس‌های همسایه را بر پایه‌ی Kafka و AsyncAPI
تصمیم‌گیری کرده است. بااین‌حال، الزام بخش ۸ تمرین فعلی صراحتاً پیاده‌سازی یک HTTP
Consumer برای endpoint زیر را می‌خواهد و تست آن را با Stub سمت Consumer ارزیابی می‌کند:

`POST /api/v1/accounts/transfer-check` در S1.

برای برآورده‌کردن این الزام، ارتباط S3 با S1 باید استثنائاً از طریق REST انجام شود.

## Decision

ارتباط S3 → S1 برای عملیات `checkTransferAccounts` از طریق HTTP REST پیاده‌سازی
می‌شود. آدرس پایه از متغیر محیطی `NEIGHBOR_BASE_URL` خوانده خواهد شد و تست Consumer
با HTTP Stub (ترجیحاً WireMock) انجام می‌شود. قرارداد درخواست و پاسخ مرجع، فایل
`openapi/S1.yaml` است.

این استثنا فقط به S1 و عملیات account transfer-check محدود است. ارتباط S3 با S2،
S4 و S5 همچنان Kafka و قراردادهای AsyncAPI باقی می‌ماند؛ API رو‌به‌فرانت‌اند S3
نیز همچنان REST و مطابق `openapi/Payment.yaml` است.

## Preconditions / Contract gaps

قرارداد S1 برای درخواست به دو مقدار `source_sheba` و `destination_sheba` و برای
احراز هویت به Bearer JWT صادرشده توسط S1 نیاز دارد. API فعلی S3 در
`openapi/Payment.yaml` به‌جای آن‌ها `source_account_number` و یکی از
`dest_account_number` یا `dest_iban` را می‌پذیرد و در قرارداد فعلی، توکن مشتری
برای این فراخوانی تعریف نشده است. شماره‌حساب محلی را نمی‌توان بدون lookup معتبر
به شبا تبدیل کرد و S3 نیز نباید توکن را جعل یا از روی داده‌ی دیگری تولید کند.

بنابراین، پیش از اتصال این Client به جریان اصلی انتقال، قرارداد ورودی/احراز هویت
S3 باید مشخص کند شباهای مبدأ و مقصد و توکن معتبر S1 چگونه در اختیار S3 قرار
می‌گیرند. تا آن زمان هیچ تبدیل ساختگی یا مقدار پیش‌فرضی مجاز نیست.

## Consequences

- تست Consumer با Stub باید درخواست HTTP واقعی S3 را به یک سرور WireMock هدایت کند؛
  Stub صرفاً نباید مستقیماً در تست فراخوانی شود.
- تست‌ها باید رفتار خود S3 را بر اساس پاسخ‌های S1 بررسی کنند، از جمله حساب مقصد
  پیدا شده/پیدا نشده، غیرفعال بودن حساب، خطاهای 400/401/404/503 و شکست ارتباط.
- این استثنا coupling زمانی REST با S1 را می‌پذیرد و فقط برای انطباق با الزام
  مشخص تمرین است؛ سایر ارتباطات بین‌سرویسی از تصمیم Kafka در ADR-0001 پیروی می‌کنند.
